Researched current (as of mid-2026) production tools, academic frameworks, and industry benchmark data before answering "is this perfect / better than what exists." Short answer: **no, it's not perfect, and it's not a replacement for the tools below or for human audit** — here's specifically why, with sources.

## Where this suite is genuinely different (not necessarily better)

- **Scope is broader, but shallower per-chain than a dedicated scanner.** These tools are audit/scan tools for *existing* code. This suite covers the full lifecycle — architecture design, code generation, wallet/deploy tooling, incident-response planning — across three completely different ecosystems (Cosmos/CosmWasm including a specific chain's whitelisting quirks, EVM, Solana), not just vulnerability scanning on one.
- **No chain in this list explicitly supports CosmWasm/Cosmos** (AuditAgent's multi-chain support is EVM+Solana+Starknet) — that's a real coverage gap in the existing tool landscape this suite fills, not a claim that this suite scans better than they do on the chains they do cover.
- **Methodology transparency**: every check this suite makes is a readable markdown file, not a black-box scan — you can read exactly what's being checked and why, and edit it. The tools above are products you query, not documents you audit yourself.
- **Multi-framework agent portability** (Claude Code Agent Teams natively, CrewAI/LangGraph/AutoGen/OpenAI Agents SDK/ADK via a mapping guide) — none of the commercial tools above are framework-agnostic in this way, they're each a specific product.

## Where this suite is genuinely behind, and why that matters

- **Zero empirical validation.** AuditAgent has a published, if modest, recall number against a real benchmark (EVMBench/SCABench) and a real production study (29 audits). This suite has never been run against EVMBench, SCABench, or any labeled ground-truth dataset. Every claim in this suite about "agency-grade" rigor is about *process* (does it follow the same phases real firms use), not about a *measured detection rate* — those are different claims, and conflating them would be dishonest. If you want a number to compare against Nethermind's ~30%, that number doesn't exist for this suite and shouldn't be assumed to be similar, better, or worse without actually running the comparison.
- **No hard PoC-execution validation gate until this pass.** The state of the art (Veritas' Discover→Validate pipeline, MOSAIC-Bench's hand-verification oracle, the POCO pattern) requires an actual executable proof-of-concept before a Critical/High finding is reported, specifically because LLM-written "exploit scenarios" can look plausible while referencing code paths, functions, or parameters that don't actually exist or don't actually work when run — a well-documented, named failure mode ("PoC pollution"). This suite's `agency-audit-methodology.md` now has this gate (added in this pass, see Phase 6.5) but it wasn't there before, and even now it's an instruction to an LLM to run a test, not an independently engineered validation harness like Veritas' two-stage pipeline — the discipline depends on whoever's running the skill actually following it.
- **Industry-wide caution about AI-only security testing applies here too.** A recent industry survey found the share of security teams relying solely on automated AI testing fell from 29% to 9% in a year, and 78% of organizations report fully-automated AI scanning misses critical vulnerabilities. Nothing about this suite's design exempts it from that pattern — if anything, a general-purpose LLM following a markdown checklist is less specialized than a tool like AuditAgent that's specifically tuned/trained on audit data, so there's no basis to assume this suite performs *better* than tools that already show real, measured, non-trivial miss rates.
- **No CI/continuous-monitoring wiring.** AuditAgent plugs into a CI pipeline; ChainGPT/Forta do live on-chain monitoring. This suite documents what monitoring/incident-response *should* look like (Phase 10 of the methodology) but doesn't ship an actual integration.

## Head-to-head: SolidityScan (CredShields) — a real, revenue-generating comparison

Requested specifically, so here it is in full rather than folded into the table above. SolidityScan is CredShields' flagship product, commercial since 2021, with a real client base — this is the most direct "are you actually better than a working business" comparison available, and the honest answer is **no, not on the dimensions that make it a real product**.

**Where SolidityScan is ahead, concretely:**
- **It's a real detection engine, not LLM instructions.** 700+ purpose-built vulnerability detectors combining static analysis with ML, running deterministically in seconds. This suite depends on an LLM correctly following a markdown checklist each time — no guaranteed determinism, no fixed detector count, and performance can vary run to run in a way a compiled scanner's doesn't.
- **Real track record.** 200+ completed audits, $10B+ in claimed protected assets, an actual enterprise client base, ISO 27001/SOC 2/PCI DSS compliance mapping. This suite has never audited a real production contract — zero track record, by definition, as of this pass.
- **Shipped integrations**, not documentation about integrations: a GitHub Action for CI/CD, a Slack integration, a Remix IDE plugin, an npm package, and — notably — its own **MCP server** (`solidityscan-mcp-server`), meaning it can be plugged directly into Claude Code or any MCP-compatible agent as an actual callable tool. This suite tells an agent to run Slither/Mythril; SolidityScan *is* a tool an agent can call.
- **Speed-optimized workflow**: "seconds, not days" for a first-pass scan with developer-ready fix suggestions and a numeric security score. This suite's deep multi-phase pipeline (scope → threat model → architecture → code → QA → static analysis → audit) is deliberately slower — minutes to hours depending on protocol size — which is a real cost when someone just wants a fast pre-commit check.
- **Same "AI + human" hybrid model** CredShields advertises ("AI handles recon and enumeration, senior researchers handle judgment") is the same pattern Nethermind's AuditAgent study converged on independently — further corroboration that AI-only, without a human or a second validation layer, isn't where the credible players in this space have landed. This suite's Phase 6.5 validation gate (added in this pass) is a step toward that, but it's still one LLM checking itself, not a separate human or a separate independently-engineered validator.

**Where this suite covers ground SolidityScan doesn't (a gap it fills, not proof of superiority):**
- SolidityScan is **EVM-only** (Ethereum, Polygon, Avalanche, BNB Chain, Rootstock, and other EVM-compatible chains) — it does not cover CosmWasm/Cosmos or Solana at all. This suite's Cosmos and Solana skills sit in a real coverage gap.
- SolidityScan audits **existing code** — it doesn't design an architecture, generate a contract from a spec, write deploy scripts, or produce an incident-response plan. This suite covers the full pre-code-to-post-deploy lifecycle; SolidityScan is one phase (static-analysis-style scanning) of that lifecycle, done better than this suite does that one phase.
- SolidityScan's OWASP Web3 Top 10 mapping is pattern/anti-pattern-level; this suite's methodology layer (threat modeling, key-compromise resilience ladder, economic/game-theoretic review, explicit scope/assumptions) goes into bespoke-protocol business-logic territory that a general-purpose pattern scanner isn't designed to reason about.

**The honest practical takeaway**: if you have access to SolidityScan (or its MCP server) or a similar commercial scanner, use it as the fast first-pass in this suite's static-analysis phase (step 6/7 in each `SKILL.md`) — the same way the skills already tell you to run Slither/Mythril — rather than treating this suite's manual checklist as a replacement for a purpose-built detector engine with a real track record. This suite's actual value-add is the phases a scanner doesn't do: architecture, threat modeling, and the full lifecycle around the code, not out-detecting a product that's been in production since 2021.

## Head-to-head: CosmWasm — a real market gap, not a real competitor

This is the one chain where research found **no self-serve automated AI scanning product** comparable to SolidityScan/RustScan. What exists instead is **Oak Security** — a real, established boutique audit firm (400+ audits total, 130+ CosmWasm-specific, credited with securing 240M+ staked ATOM's worth of Interchain Security, official audit partner for Neutron's sponsorship program, audited Sei, Babylon Genesis, Noble, Stride, and CosmWasm/wasmd core itself) — but it's a **manual-first, human-auditor business model**, not a product you self-serve scan with. No automated engine, no instant score, no CI/CD plugin comparable to SolidityScan's.

Two concrete, real disclosed vulnerabilities from Oak's public CosmWasm/wasmd core audit were folded directly into this suite's checklist in this pass (previously it only had generic categories covering the same ground, not the specific disclosed patterns):
- An **unbounded IBC channel-enumeration query** (a `ListChannels`-style query returning global chain state instead of scoping to the calling contract) becoming a growing DoS surface as the chain accumulates more channels over time — added as its own checklist item.
- A **migration-to-restricted-code-ID bypass**, where `migrate` could move a contract onto a code ID that direct instantiation would have blocked — added as its own checklist item.
- Sharpened the existing truncation/rounding item with Oak's specific documented lesson: decimal-mismatched fee math can truncate to exactly zero even for legitimate-sized amounts, and the fix is charging a 1-unit minimum, not just "round toward the protocol" in the abstract.

**The honest takeaway for CosmWasm specifically**: this suite's manual-checklist approach is comparatively more useful here than for EVM or Solana, precisely because there's no automated competitor to defer to — but "more useful than nothing automated exists" is a much weaker claim than "competitive with a measured product," and Oak Security's real audits (with a real client base and a real track record) remain the standard to compare against, not a peer.

## Honest verdict

Not perfect, and not a substitute for either a dedicated scanner (Slither/Mythril/AuditAgent/Echidna — all of which this suite tells you to actually run, it doesn't reinvent them) or a paid audit firm before real funds are at stake. Best understood as: a structured, transparent **methodology-and-orchestration layer** — the same phases and discipline real audit firms use, now with a hard PoC-validation gate — that's genuinely useful for organizing an audit and for chains (CosmWasm/ZigChain specifically) that existing commercial multi-chain tools don't cover, but it carries the same unresolved, industry-wide AI-audit limitations as every other LLM-based security tool: unmeasured recall/precision, and a validation gate whose enforcement depends on the agent actually following the instruction rather than an independently engineered check.

**Practical recommendation**: use this suite for the architecture/threat-model/methodology structure and as one input among several, run the actual static/dynamic tools it tells you to run (Slither, Foundry invariants, Trident, etc.) and treat their output as equally important, and — for anything with meaningful real value at stake — get a human audit firm involved before mainnet, the same way Nethermind's own study concluded about AuditAgent: "pair auditor," not standalone.
